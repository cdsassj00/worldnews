## 0. 인수인계 — 목표, 지금 상태, 배운 것, 다음 할 일

### 0-1. 목표 (사용자 원문 요지)

- **"나는 네가 돈을 벌어줬으면 좋겠다."** 사이트의 목적은 **종목 추천이 우선**이고, 그 종목을 **온톨로지(거시 인과)·수급·차트·종합**으로 분석해 보여 주는 것.
- 추천은 **단타·스윙·중기·장기**로 나누고, 종목마다 **목표가·손절가를 숫자로** 준다.
- 같은 추천이 사이트 · 텔레그램 · SNS/유튜브(별도 저장소 `cdsassj00/sns-automation` 이 `/api/daily-brief` 를 읽음)로 나간다. **API 한 곳만 고치면 전 채널에 반영된다.**
- 운영자는 한국투자증권(KIS) **실계좌**로 자동매매를 돌린다.

### 0-2. 사용자가 싫어하는 것 (반복해서 혼났다)

1. **"백테스트로 엔진 순위 매기기"** — 과거 시세로 규칙을 흉내 낸 것. 뉴스는 0, 수급은 가격 역산 대용품, 생존편향까지 있어 실제와 다르다. 실제로 온톨로지 국내 1년 수익률이 **사흘 만에 +4.99% → −5.14%** 로 뒤집혔다. 사용자: *"니가 추천한 종목을 샀을 때 그걸 백테스팅 해야지, 전략으로 백테스팅이 되냐."*
   - 허용되는 것: ① **실제로 나간 추천을 채점**(성적표) ② **입력이 과거에 그대로 재현되는 규칙**(가격·거래량만 쓰는 규칙)의 검증.
2. **자랑하는 화면.** 히어로가 3화면짜리 자기소개였을 때 "자랑치는 것 같다"고 했다. 처음 온 사람에게는 **"어떻게 고르는지 + 오늘 실제 숫자"**를 보여 줄 것.
3. **어려운 말·긴 글.** 보고는 **쉬운 한국어, 짧게.** 전문용어엔 풀이를 붙인다.
4. **과장.** 사실과 다른 문구(예: "세 분석이 동시에 가리키는 종목만" — 실제는 가중 합)는 고쳐야 한다. 나쁜 숫자도 그대로 보여 준다.
5. **글씨가 큰 것·톤이 섞인 것.** UI는 **네이버 증권 구조 + ssjsite 톤**(순수 블랙, iOS 회색 계단, Pretendard, 굵기 ≤600, 표 13px). 디자인 스킬은 `cdsassj00/ktv/.claude/skills/ssjsite/`.

### 0-5. 배운 것 (근거와 함께)

1. **파는 숫자를 바꿔서는 안 풀린다.** 같은 실제 추천에 목표가를 당기거나(+7/+9%) 손절을 넓혀도(−6/−8%) 평균이 플러스로 돌지 않았다(09-29 측정). → **고르는 방식(매수 신호)**을 고쳐야 한다.
2. **빠진 재료가 있다.** 거시 7개(달러인덱스·구리·나스닥·비트코인·미 단기금리·엔/달러·금)는 `shared/ontology.ts` 에 있지만 **점수(SENSITIVITY)에 안 들어간다.** 실제 외국인·기관 순매수(`realFlow`)는 가중치 0이고 `worker/` 어디서도 넘겨주지 않는다. 지금 "수급"은 가격·거래량 대용품(MFI·CLV·거래대금 급증·돌파)이다.
3. **차트 13종은 전부 같은 한 표**(`shared/ta.ts` `consensus`). 어느 전략이 맞히는지 몰랐던 건 개별 판정을 버렸기 때문 — 2026-09-26부터 스캔 행에 `ta13`(전략별 점수)을 저장한다(`worker/quant.ts`). 이걸로 **전략별 적중률**을 매길 수 있다(아직 안 만듦).
4. **거래량 폭증 + 주가 횡보 = 매집?** (사용자가 기사에서 본 이론, 10-06 측정 — `scripts/research/`)
   - 국내 350종목 2년. 최근 20일 거래량 ≥ 평소 2배 + 그중 6일 이상 1.5배 + 20일 가격 변화 ±3% 이내 → 다음 날 시가 매수.
   - 그냥 쓰면 **10일 승률 44%** (아무 종목 아무 날 49%보다 못함).
   - **그 전 60일 −10% 이상 빠진 바닥권**에서 생기면 **10일 승률 56%, 코스피보다 나은 비율 59%**(32건).
   - **많이 오른 뒤(고점권)**에 생기면 오히려 나쁨(분산 = 큰손이 파는 신호일 때가 많음).
   - 지금 수급 점수는 `shared/quant.ts` `const surge = mom5 >= 0 ? surgeRaw : -Math.abs(surgeRaw) * 0.6;` — **거래량이 터졌는데 가격이 조금 빠지면 감점**한다. 바닥권에서는 이 이론과 반대다.
5. **실계좌 허점(10-02 발견, 미수정 — 사용자 확인 대기)**
   - 체결 안 된 매도 주문을 확인하지 않아 같은 매도를 다시 보내 "주문 가능 수량 초과" 오류 4회(대한항공, 09-30).
   - 익절한 **바로 그날 같은 종목을 다시 삼**(09-30 대한항공) — 익절의 의미가 사라진다.
   - 1회 한도(180만원) 넘는 매도 나눠 팔기는 정상 작동(09-29·09-30 확인).

### 0-6. 사용자 확인을 기다리는 결정 (먼저 묻고 할 것)

1. 기존 실계좌 봇(국내 온톨로지 / 미국 fusion)을 **그대로 둘지, 성적표가 확인될 때까지 멈출지.**
2. 실계좌를 **사이트 추천과 연결**할지 — 사용자는 **B안**(2~3주 그림자 운용 후 결정, 2026-09-27 선택)을 골랐다. 10월 둘째 주쯤 다시 물을 것.
3. 실계좌 허점 2개(미체결 주문 확인 · 익절/손절 후 재매수 쿨다운) 수정.
4. 수급 점수에 **"바닥권 매집 의심"** 표시를 추가해 성적표에서 따로 채점할지.

### 0-7. 다음 할 일 (우선순위)

1. **매수 신호 개선을 성적표로 검증하는 틀** — 후보 점수(빠진 거시 7개 + 실제 외국인·기관 수급 + 바닥권 매집 표시)를 지금 점수 옆에서 **그림자로 같이 채점**하고, 실제로 더 맞히면 바꾼다.
2. **부품별 채점** — `ta13`·수급 항목·온톨로지 축을 1·3·5·10일 뒤 실제 등락과 대조 → "어느 차트 전략이 먹히나" 표. 매일 스냅샷은 KV 쓰기 1회로.
3. **종목 통합 페이지** — 종목 하나를 [종합 | 온톨로지 | 수급 | 차트] 탭으로(지금 검색은 차트 탭으로만 간다). 서버 조회 함수 `quantRow`는 만들어 둠.
4. 온톨로지 탭 3D 그래프 톤을 ssjsite 에 맞춤.

### 0-8. 절대 규칙

- **실계좌 설정(`AUTO_*`, `US_*`, KV `auto:engine`·`auto:us:engine`)은 직접 바꾸지 않는다 — 제안만.**
- 시크릿(`TELEGRAM_BOT_TOKEN`, `TRADE_TOKEN`, KIS 키 등)은 Cloudflare 시크릿으로만. 저장소에 넣지 않는다.
- 공개 공지·SNS에 계좌 금액·손익을 넣지 않는다.
- **무료 요금제 제약**: KV 쓰기 하루 1,000회(같은 값 재기록 금지 — `worker/util.ts` `cached`), 호출 1회당 외부 요청 50개. 새 작업은 이 안에서 설계할 것.
- 응답 모양이 바뀌면 캐시 키 버전을 올린다(`brief:v7` 등). 안 올리면 배포해도 옛 모양이 나간다.
- 브라우저 검증: Playwright + `/opt/pw-browsers/chromium`. 프록시 인증서 오류가 나면 `certutil` 로 `/usr/local/share/ca-certificates/*.crt` 를 `~/.pki/nssdb` 에 넣는다(TLS 검증을 끄지 말 것).

## (예전 개요 — 낡은 부분이 있음)

**거시 지표가 섹터를 거쳐 종목으로 전파되는 과정을 3D 지식그래프로 보여 주고**, 그 판단으로 매매까지 이어지는 Cloudflare Workers 사이트.

- **메인 화면 = 3D 온톨로지 그래프.** 거시요인 8개 → 섹터 14개 → 종목 20개를 세 층 고리로 세우고, 지금 실제로 흐르는 기여도만 선으로 잇는다. 선 위 점의 방향과 속도가 신호의 부호와 세기다. 노드를 누르면 그와 이어진 경로만 남는다.
- **지구본은 아이콘.** 오른쪽 아래에서 돌아가다가 누르면 세계 경제 지표 모달이 열린다. 지도에서 나라를 클릭하면 그 나라 뉴스·지수·종목 점수가 오른쪽 패널에 뜬다.
- 뉴스: Google News → Bing News → Yahoo Finance 3단 폴백 (현지어 + 한국어 기사를 합쳐 중복 제거).
- 시세: Yahoo Finance 차트 API (무인증). 43개 시장의 지수와 대표 종목.
- AI 분석: Claude(키 있으면) 또는 Cloudflare Workers AI(키 없이)로 국가별 한국어 브리핑을 만든다.
- 주문: 한국투자증권(KIS) OpenAPI. 국내(KRX)와 미국·일본·홍콩·상해·심천 종목을 매수/매도한다.
- 자동매매: 위 점수로 계획을 세우고 리스크 게이트를 통과해야 주문이 나간다. **백테스트 결과는 8장을 반드시 읽을 것 — 지수 보유를 이기지 못했다.**

> **투자 자문이 아닙니다.** 화면의 점수·의견은 공개 지표와 뉴스 키워드로 계산한 참고 자료이며 어떤 수익도 보장하지 않습니다. 매매 판단과 책임은 이용자 본인에게 있습니다.

그래서 `worker/util.ts` 의 `cached()` 는 **TTL 5분 미만은 아이솔레이트 메모리에만** 두고 KV에는 쓰지 않는다.
한도는 UTC 자정에 리셋된다. 방문량이 늘면 Workers Paid($5/월)로 올리는 것이 맞다.

## 3. 키를 어디에 넣나 (한눈에)

**모든 키는 Cloudflare 시크릿으로만 넣는다. 코드·저장소·PR에 절대 쓰지 않는다.**

| 넣는 위치 | 이름 | 무엇에 쓰이나 | 없으면 |
|---|---|---|---|
| `wrangler secret put` | `KIS_APP_KEY` | 한국투자증권 앱키 | 주문·잔고·KIS 시세 전체 잠김 |
| `wrangler secret put` | `KIS_APP_SECRET` | 한국투자증권 앱시크릿 | 위와 동일 |
| `wrangler secret put` | `KIS_ACCOUNT` | 계좌번호 `12345678-01` | 위와 동일 |
| `wrangler secret put` | `TRADE_TOKEN` | 주문·잔고 화면 접근 암호(내가 정하는 값) | `/api/kis/*` 가 503으로 잠김 |
| `wrangler secret put` | `ANTHROPIC_API_KEY` | AI 브리핑을 Claude로 처리 | Workers AI로 자동 폴백(키 불필요) |
| `wrangler.jsonc` `vars` | `KIS_ENV` | `prod`=실전(9443) / `vts`=모의(29443) | 기본 `vts` — **실전 키는 `prod` 로 바꿔야 토큰이 나온다** |
| `wrangler.jsonc` `vars` | `ORDER_DRY_RUN` | `true`면 검증만, 주문 전송 안 함 | 기본 `true` (안전) |
| `wrangler.jsonc` `vars` | `ORDER_ENABLED` / `ORDER_ALLOW_REAL` | 실주문 2단 스위치 | 기본 `false` — 실주문 불가 |
| `wrangler.jsonc` `vars` | `MAX_ORDER_NOTIONAL_KRW` | 1회 주문 한도(원) | 기본 `100000` |
| `wrangler.jsonc` `ai` 바인딩 | (키 없음) | Workers AI | 이미 설정돼 있음 |

시세(Yahoo)와 뉴스(Google·Bing)는 **키가 필요 없다**. 로컬 개발에서는 같은 이름을 `.dev.vars` 에 넣는다(git 무시됨).

```bash
# 실전 계좌 + AI(Claude) 조합 예시
npx wrangler secret put KIS_APP_KEY
npx wrangler secret put KIS_APP_SECRET
npx wrangler secret put KIS_ACCOUNT        # 12345678-01
npx wrangler secret put TRADE_TOKEN        # 길게, 추측 불가하게
npx wrangler secret put ANTHROPIC_API_KEY  # 선택 — 없으면 Workers AI 사용
# wrangler.jsonc 에서 KIS_ENV 를 "prod" 로 바꾼 뒤
```

### 주문을 실제로 켜는 순서

**모의투자 계좌가 있는 경우**

1. `KIS_ENV=vts`, `ORDER_DRY_RUN=false`, `ORDER_ENABLED=true` 로 배포 → 잔고 조회 → 1주 매수 → 체결 확인.
2. 실전 전환: `KIS_ENV=prod` + `ORDER_ALLOW_REAL=true` 를 **함께** 바꾼다. 하나만 바꾸면 서버가 거부한다.

**실전 계좌 키만 있는 경우(모의 계좌 없음)**

1. `KIS_ENV=prod` 로 배포하고 시크릿을 등록한다. `ORDER_DRY_RUN=true` 가 기본이므로 아직 아무 주문도 나가지 않는다.
2. **조회로 연결 확인**: 거래 암호를 입력하고 잔고 조회를 눌러 실제 보유 종목이 나오는지 본다(주문 스위치와 무관하게 동작).
3. **검증 모드로 전 과정 점검**: 주문 탭에서 1주 주문을 넣어 본다. 인증·한도·TR_ID까지 실제로 확인하고 KIS에는 전송하지 않는다.
4. **실주문**: `ORDER_DRY_RUN=false`, `ORDER_ENABLED=true`, `ORDER_ALLOW_REAL=true` 로 배포한다. 한도(`MAX_ORDER_NOTIONAL_KRW`)는 처음에 10만원 그대로 두고, 1주 체결을 확인한 뒤 올린다.

## 5. AI 분석

`/api/country/:cc/analysis` 는 이 서비스가 이미 계산한 지수·뉴스 제목·종목 점수와 근거를 모델에 넣고, 한국어 브리핑(3줄 요약 / 주목 종목 / 리스크 / 확인할 것)을 받아 15분 캐시한다.

- `ANTHROPIC_API_KEY` 가 있으면 **Claude**(`claude-opus-5`, 공식 SDK, JSON 스키마 강제 출력)를 쓴다.
- 없으면 **Cloudflare Workers AI** 로 폴백한다. 별도 키가 필요 없고 배포 환경에서 약 9초에 응답한다.
- 프롬프트에 "입력한 지표·뉴스만 근거로 쓰고 새 수치를 만들지 말 것", "수익을 약속하지 말 것", "한자 없이 한글로 쓸 것"을 명시했다.
- 비용 때문에 탭을 처음 열 때만 호출하고, 결과는 국가별로 캐시한다.

## 6. 보안

- **주문 API는 공개하지 않는다.** `/api/kis/*` 는 `TRADE_TOKEN` 베어러 인증을 통과해야 한다. 토큰이 없으면 503으로 잠긴다. 사이트 자체는 공개돼도 주문은 암호를 아는 사람만 낼 수 있다.
- 브라우저는 거래 암호를 `sessionStorage` 에만 두고, 서버는 저장하지 않는다.
- 주문 전송에는 이중 확인이 걸려 있다: 모달에서 **종목코드를 다시 입력**해야 하고, 서버가 그 값을 코드와 다시 비교한다.
- KIS 앱키/시크릿은 저장소·PR·이슈에 절대 넣지 않는다. 채팅·메일 등으로 노출된 키가 있다면 **KIS Developers 에서 즉시 재발급**하고 새 값으로 `wrangler secret put` 하라.
- 접근 토큰은 KV에 캐시한다(만료 10분 전 갱신). KIS는 토큰 발급 호출 빈도를 제한하므로 캐시를 끄지 말 것.

## 7. 추천 점수 계산

각 지표를 -1~+1로 정규화해 가중합한 뒤 2.5로 나눠 점수를 만든다.

| 지표 | 가중치 | 산식 |
|---|---|---|
| 단기 모멘텀 | 0.9 | 5일 수익률 / 6% |
| 중기 모멘텀 | 1.1 | 20일 수익률 / 15% |
| 20일선 대비 | 0.8 | (현재가-SMA20)/SMA20 / 6% |
| 20/60일선 배열 | 0.5 | (SMA20-SMA60)/SMA60 / 6% |
| 20일 밴드 위치 | 0.6 | 고저 구간 위치. 0.95 초과(과열)·0.1 미만(급락)은 감점 |
| 거래량 | 0.4 | 최근 거래량 / 20일 평균 |
| 뉴스 감성 | 1.0 | 종목 별칭이 걸린 기사의 긍·부정 키워드 비율(없으면 시장 전반) |
| 변동성 리스크 | 0.7 | 일변동성 2.2% 초과분을 감점 |

판정: `≥1.15` 매수 우선 검토 / `≥0.45` 분할 매수 / `>-0.45` 관망 / `>-1.15` 비중 축소 / 그 이하 매도 검토.
매매 계획은 ATR(14)로 손절 `-2×ATR`, 목표 `+3×ATR`(손익비 1.5:1)을 제시한다.

감성 분석은 LLM이 아니라 다국어 키워드 사전이다. 캐시·재현성 때문에 결정적으로 동작해야 하고, 오탐(반어법·인용)이 섞일 수 있어 점수의 한 축으로만 쓴다.
알려진 한계: "금리 인상"은 사전상 부정이지만 은행주에는 호재다 — 금리→금융 방향성은 온톨로지 축(US10Y 민감도 +0.6)이 담당하고, 뉴스 축은 그 위의 종목 고유 이벤트(수주·실적·규제)를 잡는 역할로 쓴다.

## 8. 자동매매 (온톨로지 + 리스크 게이트)

상단 **자동매매** 버튼에서 지금 무엇을 왜 사려 하는지, 무엇이 그것을 막고 있는지 전부 볼 수 있다.

### 8.1 판단 과정

```
거시 관측            8개 지표(유가·환율·미10년·SOX·코스피·상해·VIX·금)의 5일 변화율
   │                  요인별 기준폭으로 나눠 -1~1 로 정규화
   │                  + **1면 뉴스 AI 보정**: 글로벌·국내 헤드라인 20여 건을 AI가 읽고
   │                    거시요인별 단기 방향(-1~1)을 판정 → 유효 신호 = 가격 관측 + 0.4×보정
   │                    ("긴장 완화 vs 고조"처럼 사전이 못 하는 방향 판단만 AI에 맡긴다. 30분 캐시)
   ▼
온톨로지 전파        섹터 민감도표(shared/ontology.ts)를 타고 종목까지 전파
   │                  기여도 = 섹터비중 × 민감도 × 신호세기 → 경로를 문장으로 보존
   ▼
가격 신호            5/20일 모멘텀, 20·60일선 배열, 20일 밴드 위치, 거래량비, 변동성, ATR
   │
   ▼
뉴스 감성            ① 종목 전용 검색(20종목 각각 Bing 검색, 별칭 매칭·감성 채점)
   │                  ② 시장 피드에서 섹터 키워드("반도체", "정유", "은행주"…)가 걸린
   │                     기사를 섹터 감성으로 만들어 소속 비중 × 0.4 로 감쇠 반영
   │                  "코스피 하락" 같은 시장 일반 기사는 어디에도 안 걸려 자연히 배제
   ▼
합성 점수 = 온톨로지 0.35 + 가격 0.45 + 뉴스 0.20   (0.15 이상이어야 매수 후보)
```

종목 전용 뉴스는 `worker/tickernews.ts` 가 수집한다. Workers 요청당 fetch 한도(50) 때문에
한 번에 다 긁지 않고 **호출당 가장 오래된 4종목만** 검색해 KV 한 키에 누적한다(45분 신선도로 수렴).
수집 상태는 `/api/auto/tnews` 로 확인한다. 각 종목 카드에는 실제 걸린 헤드라인이 근거로 붙는다.

세 축을 섞는 이유는 실패 모드가 서로 다르기 때문이다. 온톨로지는 구조를 알지만 타이밍을 모르고,
모멘텀은 타이밍은 알지만 이유를 모르며, 뉴스는 빠르지만 잡음이 많다.
각 종목 카드를 펼치면 세 축의 기여도와 근거 문장이 그대로 나온다 — 블랙박스로 돈을 넣지 않기 위해서다.

유니버스는 **국내(KRX) 20종목**으로 제한한다. 해외 주문 TR_ID가 실계좌로 검증되지 않았고,
검증되지 않은 경로에 실제 돈을 태우지 않는다.

### 8.2 안전장치

주문이 실제로 나가려면 **네 개의 스위치를 모두** 넘어야 한다:
`AUTOTRADE_ENABLED=true` + `ORDER_ENABLED=true` + `ORDER_ALLOW_REAL=true` + `ORDER_DRY_RUN=false`.
하나라도 막혀 있으면 사이클은 그림자 실행으로 떨어져 계획만 일지에 남긴다(기본 상태).

| 항목 | 변수 | 기본값 | 동작 |
|---|---|---|---|
| 자동매매 스위치 | `AUTOTRADE_ENABLED` | `false` | 꺼져 있으면 계획만 세운다 |
| 운용 원금 | `AUTO_CAPITAL_KRW` | 2,000,000 | 계좌에 돈이 더 있어도 이 이상 쓰지 않는다 |
| 종목당 비중 | `AUTO_MAX_POSITION_PCT` | 25% | 한 종목 최대 50만원 |
| 1회 주문 | `MAX_ORDER_NOTIONAL_KRW` | 500,000 | 초과 주문은 서버가 거부 |
| 손절 / 익절 | `AUTO_STOP_LOSS_PCT` / `AUTO_TAKE_PROFIT_PCT` | -7% / +15% | 종목별 |
| 당일 정지 | `AUTO_DAILY_LOSS_HALT_PCT` | -5% | 그날 신규 매수 중단(손절 매도는 계속) |
| 영구 정지 | `AUTO_MAX_DRAWDOWN_PCT` | -20% | 사람이 `/api/auto/resume` 로 풀 때까지 중단 |
| 목표 수익 | `AUTO_TARGET_PROFIT_KRW` | 1,000,000 | 도달하면 신규 매수 중단 |
| 매매 빈도 | `AUTO_MAX_TRADES_PER_DAY` / `AUTO_MAX_ORDERS_PER_CYCLE` | 6 / 3 | |
| 동시 보유 | `AUTO_MAX_POSITIONS` | 5 | |

그 밖에:

- **장중에만 판단한다.** 평일 09:00~15:20 KST 밖에서는 주문하지 않는다(동시호가 전에 손을 뗀다).
- **봇이 산 종목만 판다.** 계좌에 원래 있던 보유분은 장부에 없으므로 건드리지 않는다.
- **정지선은 계좌 전체 평가액 기준**이다. 기존 보유분이 크게 흔들려도 정지가 걸릴 수 있는데, 이 방향의 오작동(더 빨리 멈춤)은 그대로 둔다.
- **지정가만 쓴다.** KRX 호가 단위에 맞춰 매수는 +0.3% 올려, 매도는 -0.3% 내려 낸다.
- **위험회피 국면에선 사이즈를 줄인다.** VIX·코스피로 계산한 `riskOff` 가 높으면 최대 절반까지 축소하고, 0.8 이상이면 보유분을 줄인다.
- 크론(`*/15 0-6 * * 1-5` UTC = 장중 15분 간격)이 사이클을 돌린다. 상태·포지션 장부·일지는 KV에 남는다.

### 8.3 백테스트 — 이 전략은 지수 보유를 이기지 못한다

`npm run backtest` 로 언제든 재현할 수 있다. 점수 계산은 운영과 **같은 코드**(`shared/scoring.ts`)를 쓴다.
다른 코드로 검증하면 검증이 아니기 때문이다.

| 기간 | 이 전략 | 코스피 보유 | 최대낙폭 | 매매 | 승률 | PF |
|---|---|---|---|---|---|---|
| 최근 2년 | **+50.2%** | +156.3% | -18.9% | 254건 | 37% | 1.31 |
| 최근 5년 | **-23.3%** | +119.9% | -24.0% | 53건 | 23% | 0.27 |

5년 구간에서는 **2022-03-18에 영구정지선(-20%)이 걸려 그 뒤 4년간 매매가 멈췄다.** 200만원이 153만원으로 끝났다.

규칙을 바꿔 8가지 변형을 시험했지만 어느 것도 지수 보유를 이기지 못했다(2년 구간 기준).

| 변형 | 수익률 | vs 코스피 | 최대낙폭 |
|---|---|---|---|
| 현재 설정 | +50.2% | -106.1%p | -18.9% |
| 신호이탈 매도 제거 | +39.7% | -116.6%p | -17.2% |
| 위험회피 매도 제거 | +62.2% | -94.1%p | -15.0% |
| 익절 → 추적손절 8% | **-21.8%** | -178.1%p | -22.1% |
| 손절 → 2.5×ATR | +30.9% | -125.4%p | -21.8% |
| 손절 12%로 완화 | +30.1% | -126.2%p | -22.0% |
| 추적손절만 (거의 홀딩) | +55.8% | -100.5%p | -19.8% |

읽어야 할 것은 순위가 아니라 **패턴**이다.

- **손절을 완화하면 오히려 나빠진다**(D·E). 손절이 문제의 원인이 아니라는 뜻이다.
- 2년 구간에서 제일 좋았던 "위험회피 매도 제거"는 5년 구간에서 **제일 나빴다**(-26.3%). 한 구간에서 좋은 값이 다른 구간에서 무너지는 것이 과최적화의 전형이다. 그래서 **백테스트 결과에 맞춰 파라미터를 고치지 않았다.**
- 구조적 원인은 명확하다. 손절 -7% / 익절 +15% 는 상승장에서 **수익은 잘라내고 손실은 자주 확정**한다. 승률 37% · PF 1.31 은 "작게 벌고 자주 잘리는" 시스템의 지표다.

**결론: 이 시스템은 판단 근거를 설명 가능하게 만드는 도구로는 작동하지만, 지금 규칙 그대로 돈을 맡길 근거는 없다.**
대시보드 최상단에 이 결과를 고정해 두었다.

백테스트의 한계도 그대로 적어 둔다. 뉴스 축(가중치 0.20)은 과거 재현이 불가능해 0으로 처리했고,
유니버스가 현재 살아 있는 20종목이라 생존편향이 있으며, 미체결·부분체결은 무시한다.
체결은 **다음 거래일 시가**로 잡고(같은 날 종가 체결은 미래를 보는 것이다), 손절·익절은 장중 저가·고가로 판정하며,
슬리피지 ±0.3%와 왕복 거래비용 0.23%를 반영했다.

### 8.4 예측력 평가 — "그 종목을 골랐다면 어떻게 됐나"

백테스트(위)는 자금·한도·손절이 얽힌 **전략** 시뮬레이션이라, "점수가 종목을 잘 고르는가"라는
질문에는 답하지 못한다. `npm run predict-eval` 이 그 질문만 따로 잰다: 매일 점수 상위 3(매수
기준 통과)을 다음날 시가에 샀다고 치고 1·5·20거래일 뒤 수익률을, **침팬지(같은 날 같은
유니버스 무작위 선택 = 유니버스 평균)** 와 비교한다. 무작위를 못 이기면 예측력이 없는 것이다.

2026-06 실행 결과(코어 20종목, 비용 미반영):

| 구간 | 지평 | 추천 평균 | 침팬지 | 초과 | IC(순위상관) |
|---|---|---|---|---|---|
| 최근 1년 | 20일 | +10.6% | +2.7% | **+7.8%p** | **0.120** (양인 날 69%) |
| 최근 1년 | 1~5일 | +0.3~2.1% | −0.2~+0.5% | +0.6~1.7%p | ≈ 0 (무의미) |
| 2년 | 20일 | +7.2% | +3.8% | +3.3%p | 0.028 (약함) |

읽는 법 — 세 가지가 동시에 참이다:

1. **종목 선택 예측력은 20일(약 1개월) 지평에서만 존재한다.** 1~5일 지평의 IC는 0 근처로
   동전 던지기와 같다. 약세 경고(점수 최하위)도 20일 지평에서 침팬지보다 −2.6%p 나빠
   방향이 맞는다.
2. 누적으로도 최근 1년은 비용 반영 후 추천 +8.4% vs 같은-타이밍 침팬지 −2.8% — 선택 능력이
   비용을 이긴다. 단 2년 전체로 넓히면 이 격차는 거의 사라진다(레짐 의존).
3. **그래도 코스피 지수에는 진다.** 지수 랠리가 초대형주에 집중된 구간이라 침팬지도 지수에
   진다. "지수를 이기는가"와 "종목을 고를 줄 아는가"는 다른 질문이고, 이 시스템은 후자만
   부분적으로 그렇다.

전략(8.3)이 지수에 진 구조적 이유가 여기서도 보인다: 신호의 에지는 1개월 보유에 있는데,
전략은 단기 회전과 손절로 그 에지를 깎아 먹는다. 보유 기간을 늘리는 개편은 백테스트 재검증과
함께 별도로 판단한다.

### 8.5 목표에 대해

목표는 +100만원으로 설정돼 있지만, **그 목표를 위해 손실 한도를 풀지는 않는다.**
원금 200만원에서 +50%를 보장하는 시스템은 존재하지 않는다. 한도를 풀어 목표를 좇는 조합이
계좌를 없애는 가장 흔한 경로이므로, 손절·당일정지·최대낙폭은 목표와 무관하게 항상 작동한다.
한도를 바꾸려면 `wrangler.jsonc` 의 `AUTO_*` 값을 직접 바꿔 재배포해야 한다.

덧붙이면, 백테스트 기준으로 목표 +50%는 2년이 걸렸고 같은 기간 코스피는 +156%였다.
목표 수익만 놓고 보면 **지수 ETF를 사서 들고 있는 쪽이 더 빠르고 덜 위험했다**는 뜻이다.

### 8.6 온톨로지 경로도

대시보드의 **온톨로지 경로 — 왜 이 종목인가** 블록이 판단 과정을 그림으로 보여 준다.
거시요인 → 섹터 → 종목 세 열을 잇고, 선 굵기는 기여도 크기, 빨강/파랑은 점수를 올리는/내리는 방향이다.
아래 수식 줄에 `온톨로지×0.35 + 가격×0.45 + 뉴스×0.20 = 합성점수` 가 실제 숫자로 표시된다.
그래프의 정적 구조(민감도표 전체)는 `/api/auto/graph` 로도 열려 있다.

## 9. 알려진 제약

- **KIS 포트**: KIS OpenAPI는 실전 9443 / 모의 29443 포트를 쓴다. **배포된 Worker에서 `fetch()` 로 29443 접속이 정상 동작함을 확인했다**(더미 앱키로 호출 → KIS가 403 "유효하지 않은 AppKey입니다"를 1.7초에 응답). 혹시 `fetch()` 가 막히는 경우를 대비해 `cloudflare:sockets` 로 TLS 직결하는 HTTP/1.1 폴백을 넣어 두었고, 어느 방식이 통했는지 KV에 기억해 다음 호출에서 낭비하지 않는다(`/api/kis/status` 의 `transport`).
- **해외주식 TR_ID**: 국내 주문 TR_ID는 검증됐지만 해외 시장 TR_ID는 KIS 문서 기준 표를 코드에 넣어둔 값이다. 계좌 종류에 따라 다를 수 있으니 첫 주문은 1주로 시험하고, 다르면 `KIS_TRID_OVERRIDES` 로 덮어쓴다. KIS 오류 메시지(`msg1`)는 화면에 그대로 노출된다.
- **해외주식은 지정가만** 지원한다(KIS 제약). 시장가는 국내만 가능하다.
- 필리핀·베트남·UAE 등 일부 시장은 Yahoo 개별종목 시세가 없어 지수·뉴스만 제공하거나 ETF 프록시로 대체한다(`shared/markets.ts` 의 `proxyNote`).
- 시세는 Yahoo 일봉 기준이라 실시간이 아니다. 정확한 실시간 호가는 KIS 연동 후 `/api/kis/price` 를 쓴다.
- **뉴스 제공처**: Cloudflare Workers egress 에서는 Google News RSS 가 응답하지 않는다(요청이 타임아웃된다). 그래서 Google → Bing News RSS → Yahoo Finance 검색뉴스 순으로 폴백하고, 실패한 계열은 30분간 건너뛴다. 실제 배포에서는 Bing 이 한국어·현지어 모두 정상이라 국가별 기사가 채워진다. 뉴스 탭은 어떤 제공처가 응답했는지 함께 보여준다(`sources`).
- 한국어 피드는 검색어가 느슨해 무관한 기사가 섞이므로 국가명·시장 용어가 포함된 기사만 남긴다(`KO_ALIASES`).
- 시세·뉴스 모두 무인증 공개 엔드포인트라 호출 한도나 정책 변경에 영향을 받을 수 있다. 실패 시 만료 캐시로 버티고 화면에 상태를 표시한다.
- **자동매매 체결 확인**: 주문 접수는 장부에 낙관적으로 기록하고, 실제 보유 수량은 다음 사이클의 잔고 조회로 맞춘다. 미체결 지정가는 자동 취소하지 않으므로 필요하면 `/api/kis/cancel` 로 직접 취소한다.
- **섹터 민감도는 가정이다.** `shared/ontology.ts` 의 값은 국내 시장의 통상적 반응을 보수적으로 넣은 것이지 회귀분석 결과가 아니다. 방향은 맞아도 크기는 시기에 따라 달라진다.
- 자동매매 사이클 한 번은 시세 28건 + 뉴스 + 잔고 조회를 쓴다. Workers 요청당 서브리퀘스트 한도(무료 플랜 50) 때문에 유니버스를 20종목으로 묶어 두었고, 전략 결과는 5분 캐시한다.
